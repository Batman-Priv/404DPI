## این پروژه اصلاً چیه؟

404DPI یه پروکسی هست که روی سیستم خودت (کامپیوتر یا سرور شخصی‌ت) اجرا می‌شه و ترافیک اینترنتت رو طوری تغییر شکل می‌ده که فیلترینگ/DPI شبکه راحت‌تر نتونه شناساییش کنه و مسدودش کنه. برنامه به‌صورت خودکار روش‌های مختلفی رو امتحان می‌کنه تا ببینه کدومشون روی شبکهٔ تو جواب می‌ده، و بعدش همون روش رو یادش می‌مونه تا دفعات بعدی سریع‌تر وصل بشی.

نکتهٔ مهم: این ابزار **وی‌پی‌ان نیست** و ترافیکت رو ناشناس نمی‌کنه؛ فقط کمک می‌کنه ارتباط رمزنگاری‌شدهٔ خودت (HTTPS/TLS) راحت‌تر برقرار بشه، بدون اینکه کسی وسط بایسته و محتواش رو ببینه.

این راهنما کاملاً روی **نحوه نصب و استفاده** تمرکز داره. اگه دنبال جزئیات فنی و مکانیزم داخلی هستی، توی کد پروژه و توضیحات انگلیسیش می‌تونی پیداش کنی.

## پیش‌نیازها

- **Go نسخهٔ ۱.۲۰ یا بالاتر** (اگه می‌خوای خودت از سورس بیلدش کنی). از [go.dev](https://go.dev/) دانلود کن.
- ویندوز، لینوکس یا مک - هر سه پشتیبانی می‌شن (البته بعضی امکانات مثل حالت Transparent فقط روی لینوکس کار می‌کنن که پایین‌تر توضیح می‌دم).
- دسترسی ترمینال/Command Prompt.

نیازی به نصب هیچ برنامهٔ جانبی دیگه‌ای نیست؛ 404DPI هیچ وابستگی بیرونی نداره.

---

## نصب

### روش ۱: کلون کردن و بیلد کردن (بهترین روش)

```bash
git clone https://github.com/Batman-Priv/404DPI
cd 404DPI

go mod tidy
go build -o 404DPI .
```

اگه ویندوز داری، خروجی می‌شه `404DPI.exe`.

بعد از بیلد، برنامه رو اجرا کن ببین بالا میاد:

```bash
404DPI -h
```

اگه لیست دستورها رو دیدی، یعنی همه‌چی درسته.

### روش ۲: نصب مستقیم با go install

اگه Go روت نصبه و می‌خوای مستقیم آخرین نسخه رو بگیری:

```bash
go install github.com/Batman-Priv/404DPI@latest
```

باینری توی مسیر `GOPATH/bin` قرار می‌گیره (معمولاً `~/go/bin`)، مطمئن شو این مسیر توی `PATH` سیستمت هست تا بتونی مستقیم بنویسی `404DPI` و اجرا بشه.

## اولین اجرا

بدون هیچ فلگی، همین‌جوری اجراش کن:

```bash
404DPI
```

می‌بینی که یه پیام شبیه این میاد:

```text
HTTP proxy:  127.0.0.1:8881
HTTPS proxy: 127.0.0.1:8881
```

یعنی الان یه پروکسی روی پورت `8881` بالا اومده و منتظره که ترافیک بهش وصل بشه. برای تست می‌تونی توی یه ترمینال دیگه این رو بزنی:

```bash
curl -x http://127.0.0.1:8881 https://example.com/
```

اگه جواب گرفتی، یعنی همه‌چی داره درست کار می‌کنه.

> **نکته دربارهٔ سرعت اولین اتصال:** وقتی برای اولین بار به یه دامنهٔ جدید وصل می‌شی، برنامه چند تا روش رو پشت سر هم امتحان می‌کنه تا ببینه کدوم جواب می‌ده، پس ممکنه چند ثانیه طول بکشه. از اتصال دوم به بعد، همون دامنه سریع وصل می‌شه چون روش موفق رو یادش مونده.

## وصل کردن مرورگر یا برنامه به پروکسی

بعد از اینکه 404DPI رو اجرا کردی، باید به مرورگر یا سیستم‌عاملت بگی از این پروکسی استفاده کنه:

### روش ساده: تنظیمات پروکسی مرورگر یا سیستم‌عامل

توی تنظیمات شبکهٔ مرورگر (کروم، فایرفاکس و...) یا سیستم‌عامل، پروکسی HTTP/HTTPS رو روی:

- آدرس: `127.0.0.1`
- پورت: `8881`

قرار بده. از این به بعد ترافیک مرورگرت از داخل 404DPI رد می‌شه.

### روش پیشنهادی‌تر: با یه اکستنشن مدیریت پروکسی

برای اینکه راحت‌تر بتونی پروکسی رو روشن/خاموش کنی یا فقط بعضی سایت‌ها رو ازش رد کنی، می‌تونی از اکستنشن‌های مدیریت پروکسی مرورگر (مثل SwitchyOmega) استفاده کنی و آدرس بالا رو توش وارد کنی.

---

## کدوم پریست (تنظیمات آماده) رو انتخاب کنم؟

اگه نمی‌دونی از کجا شروع کنی، به‌جای تنظیم تک‌تک گزینه‌ها، چهار تا بسته آمادهٔ تنظیمات وجود داره:

| پریست | دستور | مناسب برای |
|---|---|---|
| ساده و محتاطانه | `-preset safe` | شروع کار، شبکه‌هایی که فیلترینگ سبک‌تری دارن |
| قدرتمندتر | `-preset aggressive` | وقتی حالت safe جواب نداد و می‌خوای برنامه از همهٔ ترفندها استفاده کنه |
| مخفی‌کاری بیشتر | `-preset stealth` | وقتی شبکه به شکل اتصالت (fingerprint) حساسه |
| شبیه وی‌پی‌ان | `-preset vpn-like` | وقتی می‌خوای هم SOCKS5 داشته باشی هم DNS امن هم بلاک QUIC |

مثال استفاده:

```bash
404DPI -preset safe
```

اگه بخوای یه تنظیم خاص رو دستی عوض کنی ولی بقیه رو از پریست بگیری، مشکلی نیست - هر فلگی که دستی بزنی روی پریست اولویت داره:

```bash
404DPI -preset aggressive -socks5-port 1081
```

### راه پیشنهادی برای شروع، قدم‌به‌قدم

اگه واقعاً نمی‌دونی شبکه‌ت به چی نیاز داره:

```bash
# اول ببین شبکه‌ت الان چه وضعی داره
404DPI -scan

# با یه تنظیم ساده شروع کن
404DPI -preset safe

# اگه کافی نبود، یه روش قوی‌تر رو امتحان کن
404DPI -fragment-method natural -adaptive

# اگه برنامه‌ت به SOCKS5/DNS امن نیاز داره اضافه‌شون کن
404DPI -socks5 -doh
```

فعال کردن همهٔ امکانات با هم لزوماً بهتر نیست - فقط کندتر می‌شه بدون اینکه لزوماً فایده‌ای داشته باشه. بهتره قدم‌به‌قدم اضافه کنی و ببینی چی جواب می‌ده.

---

## استفاده از SOCKS5 (پیشنهاد می‌شه)

خیلی از برنامه‌ها (مثل تلگرام یا بعضی اپ‌ها) به‌جای پروکسی HTTP، پروکسی SOCKS5 می‌خوان. برای فعال کردنش:

```bash
404DPI -socks5 -socks5-host 127.0.0.1 -socks5-port 1080
```

بعدش توی تنظیمات برنامه‌ت، پروکسی SOCKS5 رو با آدرس `127.0.0.1` و پورت `1080` وارد کن.

برای تست با curl:

```bash
curl --proxy socks5h://127.0.0.1:1080 https://example.com/
```

(دقت کن نوشتیم `socks5h` نه `socks5` - این باعث می‌شه اسم دامنه به خود پروکسی فرستاده بشه، که برای درست کار کردن باقی امکانات لازمه.)

## تغییر DNS به DNS-over-HTTPS

اگه فکر می‌کنی مشکل از سمت DNS شبکه‌ته (مثلاً DNS دستکاری شده)، می‌تونی DNS رو هم از داخل 404DPI رد کنی:

```bash
404DPI -socks5 -doh -doh-server "https://1.1.1.1/dns-query"
```

می‌تونی چند تا سرور DNS رو با کاما جدا کنی تا اگه یکی جواب نداد، بعدی امتحان بشه:

```bash
404DPI -doh -doh-server "https://1.1.1.1/dns-query,https://8.8.8.8/dns-query"
```

اگه هم از قبل IP واقعی یه دامنه رو می‌دونی و می‌خوای مستقیم همون رو بهش بدی (بدون درخواست DNS اصلاً)، یه فایل بساز:

```text
# hosts.txt
203.0.113.10 example.test
```

```bash
404DPI -doh -hosts-file hosts.txt
```

## استفاده از فایل کانفیگ به‌جای تایپ کردن دستور طولانی

اگه هر بار می‌خوای با یه سری تنظیمات ثابت اجرا کنی، بهتره یه فایل کانفیگ بسازی تا لازم نباشه فلگ‌های طولانی رو هر بار تایپ کنی. یه فایل به اسم مثلاً `404DPI.conf` بساز:

```ini
host = 127.0.0.1
port = 8881

fragment-method = natural
adaptive = true

socks5 = true
socks5-host = 127.0.0.1
socks5-port = 1080

doh = true
doh-server = https://1.1.1.1/dns-query

stats-http = true
stats-port = 9090
```

و اجراش کن با:

```bash
404DPI -config 404DPI.conf
```

اگه خط اشتباهی توی فایل باشه، برنامه کرش نمی‌کنه - فقط همون خط رو نادیده می‌گیره.

## بلک‌لیست: فقط سایت‌های فیلتر رو از پروکسی رد کن

اگه دلت نمی‌خواد **همهٔ** ترافیکت از پروسهٔ فرگمنت‌کردن رد بشه (که کندتره)، می‌تونی یه لیست از دامنه‌های فیلترشده بسازی و فقط همون‌ها رو دستکاری کنه:

```bash
cp blacklist.txt.example blacklist.txt
```

فایل `blacklist.txt` رو باز کن و دامنه‌های موردنظرت رو یکی زیر یکی بنویس (هر خط با `#` می‌تونه کامنت باشه):

```text
# blacklist.txt
example-filtered-site.com
another-filtered.net
```

بعد اجرا کن:

```bash
404DPI -blacklist blacklist.txt
```

### گزینه‌های مربوطه

- `-no-blacklist` → بلک‌لیست رو کلاً غیرفعال می‌کنه (همه‌چی رو دستکاری می‌کنه).
- `-autoblacklist` → به‌جای اینکه خودت لیست بسازی، برنامه از روی اتصال‌های ناموفق یاد می‌گیره کدوم دامنه‌ها فیلترن و خودش لیست رو می‌سازه.
- `-domain-matching loose` → اگه می‌خوای زیردامنه‌ها هم شامل بشن (پیش‌فرض فقط تطبیق دقیقه).

> نکته: خود فایل بلک‌لیستت ممکنه اطلاعاتی دربارهٔ شبکه‌ت لو بده، پس اگه پروژه رو جایی به اشتراک گذاشتی، بلک‌لیست شخصیت رو commit نکن.

## تنظیمات اختصاصی برای یک دامنهٔ خاص

اگه یه سایت خاص رفتار متفاوتی نیاز داره (مثلاً باید فرگمنت‌بندی متفاوتی داشته باشه)، می‌تونی توی همون فایل کانفیگ براش پروفایل جدا بسازی:

```ini
fragment-method = natural
adaptive = true

[profile: example.com]
fragment-method = sni
fragment-min = 8
fragment-max = 24

[profile: *.example.net]
fragment-method = random
```

با `*.` می‌تونی همهٔ زیردامنه‌ها رو هم پوشش بدی.

اگه لینوکس داری و می‌خوای بدون ری‌استارت کردن برنامه، فقط همین پروفایل‌ها رو رفرش کنی:

```bash
kill -HUP "$(pidof 404DPI)"
```

## حالت Transparent (بدون تنظیم پروکسی در هر برنامه) - فقط لینوکس

اگه می‌خوای همهٔ ترافیک سیستم بدون نیاز به تنظیم پروکسی در هر برنامه، خودکار از 404DPI رد بشه (فقط روی لینوکس):

```bash
sudo iptables -t nat -A OUTPUT -p tcp --dport 443 -j REDIRECT --to-port 12345
sudo iptables -t nat -A OUTPUT -p tcp --dport 80  -j REDIRECT --to-port 12345

sudo 404DPI -transparent -transparent-port 12345
```

این حالت روی ویندوز و مک پشتیبانی نمی‌شه؛ اونجا باید از تنظیم پروکسی معمولی (HTTP یا SOCKS5) استفاده کنی.

## وصل کردن به یه پروکسی دیگه (chain)

اگه از قبل یه پروکسی یا وی‌پی‌ان دیگه داری و می‌خوای 404DPI ترافیکش رو از اون رد کنه (به‌جای وصل شدن مستقیم):

```bash
404DPI -out-host 127.0.0.1 -out-port 1081 -out-type socks5 \
         -out-username USER -out-password PASSWORD
```

این کاملاً جدا از پورتیه که برنامه‌های خودت بهش وصل می‌شن.

## داشبورد مانیتورینگ

می‌تونی یه داشبورد ساده و آماری از وضعیت اتصال‌ها داشته باشی:

```bash
404DPI -stats-http -stats-port 9090
```

بعدش توی مرورگر برو به `http://127.0.0.1:9090` تا ببینی:

- تعداد اتصال‌های موفق/ناموفق
- تنظیمات فعلی برنامه
- اینکه کدوم روش برای کدوم دامنه جواب داده (و چقدر روش قابل اعتماده)

این داشبورد فقط نمایشیه و از بیرون (غیر از خودت) قابل دسترسی نیست.

## اگه وصل نشد چیکار کنم؟ (عیب‌یابی)

### قدم اول: ببین شبکه‌ت چه وضعی داره

```bash
404DPI -scan
```

این دستور بدون اینکه پروکسی رو روشن کنه، وضعیت اتصال معمولی، اتصال با فرگمنت‌بندی و DNS رو با هم مقایسه می‌کنه تا بفهمی مشکل دقیقاً کجاست.

### قدم دوم: مطمئن شو خود برنامه سالمه

```bash
404DPI -selftest
```

اگه همه‌چی سبز بود (خروجی موفق)، یعنی مشکل از خود برنامه نیست.

### قدم سوم: مقایسهٔ روش‌های مختلف

```bash
404DPI -benchmark -scan-domains "example.com,example.org"
```

نشونت می‌ده کدوم روش فرگمنت‌بندی روی شبکه‌ت بهتر جواب می‌ده و سرعتش چقدره.

### چند نکتهٔ رایج

- مطمئن شو مرورگر/برنامه‌ت واقعاً روی همون پورتی تنظیم شده که 404DPI روش بالا اومده (پیش‌فرض `8881`).
- اگه از SOCKS5 استفاده می‌کنی، حتماً `socks5h` رو به‌جای `socks5` بزن تا دامنه به خود پروکسی فرستاده بشه.
- یه روش همیشه روی همهٔ شبکه‌ها جواب نمی‌ده - اگه `safe` جواب نداد، `aggressive` یا `stealth` رو امتحان کن.
- اگه بعضی سایت‌های خاص با فرگمنت‌بندی به مشکل می‌خورن (به‌جای بهتر شدن بدتر می‌شن)، اون دامنه رو با `-fragment-method none` توی پروفایل مخصوصش استثنا کن.

## حریم خصوصی: چی روی دیسک ذخیره می‌شه؟

به‌صورت پیش‌فرض، اسم دامنه‌هایی که توی فایل‌های لاگ یا کش استراتژی ذخیره می‌شن، به‌جای متن ساده، به‌صورت یه کد رمزی (توکن) ذخیره می‌شن - یعنی کسی که فایل‌های روی دیسکت رو ببینه، مستقیم نمی‌فهمه کجاها رفتی. اگه به هر دلیلی می‌خوای دامنه‌های واقعی رو به‌صورت خوانا ذخیره کنه (مثلاً برای دیباگ کردن خودت):

```bash
404DPI -log-domains
```

این کار رو فقط روی سیستمی بزن که اگه تاریخچهٔ مرورت توی فایل بمونه، برات مشکلی نداره.

---

## جدول کامل دستورها

برای دیدن لیست کامل و همیشه به‌روز دستورها، همیشه بهتره خود برنامه رو بپرسی:

```bash
404DPI -h
```

ولی برای مرجع سریع:

| دستور | کاربرد |
|---|---|
| `-config path` | خوندن تنظیمات از یه فایل کانفیگ |
| `-preset name` | استفاده از یه بستهٔ تنظیمات آماده (`safe`/`aggressive`/`stealth`/`vpn-like`) |
| `-host` / `-port` | آدرس و پورت پروکسی HTTP (پیش‌فرض `127.0.0.1:8881`) |
| `-auth-username` / `-auth-password` | نیاز به یوزر/پس برای وصل شدن به خود پروکسی |
| `-out-host` / `-out-port` / `-out-type` | وصل شدن زنجیره‌ای به یه پروکسی دیگه |
| `-blacklist path` | مسیر فایل بلک‌لیست |
| `-no-blacklist` | خاموش کردن بلک‌لیست |
| `-autoblacklist` | یادگیری خودکار دامنه‌های فیلترشده |
| `-fragment-method` | روش تکه‌تکه کردن ترافیک (`sni`/`natural`/`random`/`multi`/`none`) |
| `-adaptive` | یادگیری خودکار بهترین روش برای هر دامنه (پیش‌فرض روشنه) |
| `-race-strategies` | امتحان چند روش هم‌زمان به‌جای پشت‌سرهم |
| `-fake-packet` | ارسال بستهٔ فریبنده (decoy) |
| `-fake-sni value` | جایگزین کردن SNI واقعی (احتیاط کن، پایین‌تر توضیح داره) |
| `-front-map real=front` | دامین فرانتینگ (پنهان کردن مقصد واقعی پشت یه دامنهٔ دیگه) |
| `-tls-profile` | شبیه‌سازی امضای TLS یه مرورگر خاص (`chrome`/`firefox`/`safari`/`edge`) |
| `-socks5` / `-socks5-host` / `-socks5-port` | فعال کردن پروکسی SOCKS5 |
| `-doh` / `-doh-server` | استفاده از DNS-over-HTTPS |
| `-hosts-file path` | تعیین دستی IP بعضی دامنه‌ها |
| `-quic-mode` | مدیریت ترافیک QUIC (`off`/`drop`/`delay`/`inspect`) |
| `-transparent` | حالت شفاف بدون نیاز به تنظیم پروکسی (فقط لینوکس) |
| `-stats-http` / `-stats-port` | فعال کردن داشبورد مانیتورینگ |
| `-scan` | تست وضعیت شبکه و خروج |
| `-benchmark` | مقایسهٔ روش‌های مختلف و خروج |
| `-selftest` | تست سلامت خود برنامه و خروج |
| `-log-domains` | ذخیرهٔ اسم واقعی دامنه‌ها به‌جای توکن رمزی |
| `-quiet` | خاموش کردن نمایش آمار زنده توی ترمینال |

## سوالات متداول

**آیا 404DPI جای وی‌پی‌ان رو می‌گیره؟**
نه. این یه پروکسی محلیه که کمک می‌کنه اتصال HTTPS معمولیت راحت‌تر برقرار بشه؛ IP یا هویتت رو مخفی نمی‌کنه.

**چرا اولین اتصال به یه سایت کند شد ولی دفعات بعد سریع بود؟**
چون برنامه اولین بار داره چند روش رو امتحان می‌کنه تا ببینه کدوم جواب می‌ده. بعدش همون روش رو کش می‌کنه و دفعات بعد مستقیم همون رو استفاده می‌کنه.

**اگه یه سایت اصلاً فیلتر نیست ولی با 404DPI کندتر شد چیکار کنم؟**
برای اون دامنهٔ خاص یه پروفایل با `-fragment-method none` بساز تا بدون دستکاری مستقیم رد بشه.

**می‌تونم روی گوشی هم ازش استفاده کنم؟**
404DPI روی خود گوشی اجرا نمی‌شه، ولی می‌تونی روی یه کامپیوتر یا سرور کوچیک اجراش کنی و گوشیت رو (با تنظیم پروکسی HTTP یا SOCKS5 توی وای‌فای) بهش وصل کنی.

**چطور بفهمم کدوم preset یا تنظیمات برام بهتره؟**
با `-scan` و `-benchmark` شروع کن؛ این دو تا دستور بهت می‌گن شبکه‌ت دقیقاً به چی نیاز داره، به‌جای اینکه حدس بزنی.

## محدودیت‌ها

- هیچ روشی روی همهٔ شبکه‌ها تضمینی جواب نمی‌ده - هر شبکه یه رفتار متفاوت داره.
- دامین فرانتینگ به زیرساخت CDN مقصد وابسته‌ست و همیشه کار نمی‌کنه.
- حالت Transparent فقط روی لینوکس در دسترسه.
- این ابزار ناشناس‌سازی (anonymity) ارائه نمی‌ده - فقط مانع دستکاری/بلاک شدن اتصال رمزنگاری‌شده می‌شه.

## نکات مهم نسخه‌ی اصلاح‌شده

- **blacklist یعنی «لیست دامنه‌هایی که به bypass نیاز دارن».** دامنه‌های داخل لیست شکسته (fragment) می‌شن و بقیه مستقیم رد می‌شن؛ هیچ‌وقت ۴۰۳ برنمی‌گرده. با `-no-blacklist` همه‌ی مقصدها bypass می‌شن.
- **گزینه‌هایی که ClientHello رو بازنویسی می‌کنن اتصال TLS واقعی رو می‌شکنن:** `-fake-sni`، `-fake-sni-pool`، `-front-map`، `-tls-profile`، `-tls-shuffle`، `-tls-grease`، `-ech-grease`، `-tls-padding`. (برنامه خودش handshake رو hash کرده و پراکسی TLS رو terminate نمی‌کنه.) فقط fragmentation ساده امن و کارا است. هیچ preset‌ای این گزینه‌ها رو روشن نمی‌کنه.
- `-fake-packet` تجربی و غیرقابل‌اتکا است و دیگه خودکار فعال نمی‌شه.
